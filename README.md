# INVOICE-MATCHING-AGENT

-   **Author**: Haizea Rumayor Lazkano
-   **Last update**: November 2026

------------------------------------------------------------------------

This GitHub project develops an LLM agent that matches supplier invoices to purchase orders, built around **evaluation first**: a reproducible dataset with ground truth, an evaluation harness and a baseline come before any agent logic.

> **Status:** work in progress.

## Overview

Matching invoices to purchase orders is a common task in finance operations: an order may be invoiced in one or several invoices, amounts and descriptions do not always match exactly, and some invoices do not belong to any order at all.

The motivation behind this project:

1. **Evaluating agents, not only building them**: every design decision is measured against a ground truth generated together with the data.
2. **Separating judgement from calculation**: the language model decides which invoice belongs to which order; balances and order states are computed by deterministic code.
3. **Running locally**: a small local LLM and a self-written tool-calling loop, so that the agent's behaviour stays inspectable.

## Key Features

- **Relational Database**: SQLite schema for subsidiaries, products, purchase orders and order lines, rebuilt from a versioned schema before every evaluation run.
- **Synthetic Data with Ground Truth**: invoices generated from YAML configuration and a fixed seed, with the correct matches written by the generator itself.
- **Hard Cases by Design**: decoy orders so that matching is not trivial, and invoices from another subsidiary that the agent must *not* match.
- **Two Separate Metrics**: matching accuracy and consolidation (final order state and balance), because an error in one can be hidden in the other.
- **Exact Amounts**: amounts stored as text and handled with `Decimal`, never `float`, since balances are compared against zero.

## Project Structure

- **src/**: Python source code (`src/db/` contains the database schema and initialization script).
- **data/**: Local data generated by the project (not versioned).
- **requirements.txt**: List of Python dependencies for the project.
